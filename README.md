# Banking Transaction Processing Pipeline

## Overview

This project implements a serverless banking transaction processing pipeline using AWS services and Terraform as Infrastructure as Code (IaC). The objective of the pipeline is to simulate a simple anti-fraud banking system that evaluates transactions and classifies them depending on their risk level.

The complete infrastructure was deployed automatically using Terraform and GitHub Actions, without creating resources manually from the AWS console during the final deployment process.

The architecture follows the required structure from class:

- 3 AWS Lambda functions
- 1 AWS Step Function with a Choice state
- Amazon S3 for result storage

The pipeline receives a JSON transaction as input, validates the information, evaluates the risk level, and finally routes the transaction to the correct folder in S3 depending on the result.

---

# Architecture

The workflow of the pipeline is the following:

```text
Input JSON
   ↓
Validate Lambda
   ↓
Risk Assessment Lambda
   ↓
Choice State
   ↓
Route Lambda
   ↓
Amazon S3
```

# Pipeline Logic

## 1. Validate Lambda

The first Lambda validates the input data before continuing the execution.

It verifies:

- The transaction amount is greater than 0
- The country code has exactly 2 characters
- The account field has a valid format

If any validation fails, the execution stops and returns an error.

If the validation is successful, the Lambda adds the following field to the event:

```json
"validated": true
```

---

## 2. Risk Assessment Lambda

The second Lambda calculates the transaction risk level.

The transaction is classified as:

- `high` risk if:
  - amount > 10000
  - OR country is different from `"MX"`

- `low` risk otherwise

This Lambda adds a new field to the JSON:

```json
"risk_level": "high"
```

or

```json
"risk_level": "low"
```

---

## 3. Choice State

The Step Function contains one Choice state that evaluates the `risk_level` field generated by the previous Lambda.

- If `risk_level == high`
  → the transaction goes to the review path

- Otherwise
  → the transaction goes to the approved path

The Choice state only routes the execution. It does not calculate the risk itself.

---

## 4. Route Lambda

The final Lambda stores the transaction result in an S3 bucket.

Depending on the risk level:

- High risk transactions are stored in:

```text
review/
```

- Low risk transactions are stored in:

```text
approved/
```

Each transaction is saved as a JSON file.

# Example Input

## High Risk Example

```json
{
  "transaction_id": "tx-100",
  "account": "1234-5678",
  "amount": 20000,
  "country": "MX",
  "merchant": "Amazon"
```

Result:

```text
review/tx-100.json
```

Result:

```text
approved/tx-101.json
```

# Deployment

The infrastructure can be deployed automatically using GitHub Actions.

The workflow performs:

- Terraform initialization
- Terraform validation
- Terraform apply

The deployment process is fully automated from the GitHub Actions interface using `workflow_dispatch`.

---

# CI/CD Workflow

This project includes a GitHub Actions workflow that allows deploying the complete infrastructure directly from the repository.

The workflow uses AWS credentials stored securely as GitHub Secrets.

The workflow can be executed manually from:

```text
GitHub → Actions → Deploy Banking Pipeline → Run workflow
```

# Running the Pipeline

Example execution:

```bash
aws stepfunctions start-execution \
  --state-machine-arn "YOUR_STATE_MACHINE_ARN" \
  --input file://test_high.json
```
